## 3. 核心行為契約

### R-01 需求與原話

白皮書要求：CBP 的時間窗、對象及關係、核心議題、排除項應清楚；復述確認後執行。

工程提案：每筆有效目標／限制須帶原始訊息來源、案件識別與確認狀態。使用者明確修正同一案件同一欄位時，新值成為本次執行依據，舊值保留為歷史；未提及的限制不丟失。指稱不明時保留歧義，不能擅選人物或案件。明確改需求不計成 AI 偏離。

原始使用者輸入、模型復述、使用者修正與最終執行依據分開記錄；不得把模型的推論回寫成使用者原話。不要求儲存或公開模型的內部思考過程。

### R-02 記憶生命週期與適用範圍

白皮書要求：人物與事件分線；停用不刪原文；知識冷卻後由使用者裁決（§8.1.5）。

工程提案：本次活動的限制預設只適用本案，不能單次推廣成永久偏好；提問紀錄與可用作事實的記憶分開。必須區分原話、已確認理解、未確認推論、待確認舊記憶及已停用記憶。這些是邏輯狀態，不強迫使用者在產品介面閱讀工程欄位。

`pending_confirmation` 被檢索到不得自動升級；`superseded` 不得作為當前有效前提注入。明確恢復／停用需更新整個對應 start/end 事件，保留狀態來源與原始內容；未知 ID 回傳未找到且不改檔。舊資料遷移須保留備份，不能由欄位缺失推定已獲使用者確認。

### R-03 查表與資訊不足

白皮書要求：生成流程前強制查本地資料，結果可空；取 top-30；有已知與未知清單。

現行工程預算：單次選取的歷史片段最多 30 筆、9,000 字元。這不是整個 prompt 或金額上限。明示本次輸入已提供的預算等條件，即使歷史未命中，也不應被重新問成未知。

工程提案：分開表示「歷史無紀錄」「本次尚未提供」「存在矛盾」「資料過期」。保留選取、略過及待確認的記憶 ID。`/check` 延續查本地留紀錄、但不把私人歷史注入外部訊息查核 prompt 的現有界線。

### R-04 資訊分層與 RBH

白皮書要求：Zone A 無可追溯來源降為 B；Zone B 推測性洞察具有 observable_behavior、trigger_context、counter_evidence、collection_method 四欄；立場以 C 表達。

工程提案：來源存在、來源已讀、來源支持主張、獨立交叉核對分開記錄。只有網址時不得標成已查證。混合句子的各主張分別標示，不用一個網址把整段升級為 A。

RBH 檢查分兩層：程式確認必要欄位、格式、可追溯證據與已知空泛樣板；人工／實測確認反例是否真的反駁該假設。兩者成績分列，不把非空字串視為語意驗收通過。

**失敗路徑提案**：具體反例不足時，不編造，也不交付為合格洞察；可在既有生成預算內補正，仍不合格則移除／保留在內部待驗證紀錄，對使用者明說不足以形成該假設，保留其餘合格內容。WP §4.4 的 ATL-1 阻擋與 §4.2 的 ATL-3 降級是不同條件；不能用 ATL-3 的降級通道繞過 ATL-1。

### R-05 最後交付版本與停止條件

白皮書要求：適用的 ATL 在交付前執行；ATL-3 初次生成加最多兩次修正，仍失敗則明標降級；CIP-X 在理解偏移等條件下交回使用者決策。

工程提案：所有最終重寫共享一份生成預算；最後送到使用者的內容，必須對應最後一次 audit 的版本。內容被改寫即令舊 audit 失效，不能沿用之前的 passed。諮詢與普通冷卻的例外需記錄理由；保留對來源及資訊誠實性的檢查。語意不確定不得默認通過。

需求澄清、情緒調整及危險請求處理分開記錄；一般理解修正不得混成危險拒絕。更細的情緒與偏移規則見待裁決表。
