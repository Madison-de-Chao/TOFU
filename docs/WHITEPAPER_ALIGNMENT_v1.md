## 定義與驗收範圍

本輪「補齊」定義為：既有 CLI 核心可安裝、跨模型 transport 可用、可定位的治理漏洞修正、資料與驗證邊界可查。未以「完整落地」掩蓋白皮書自身的規格差異。

六步工作流程：定義（以上範圍）→拆詞（儲存與傳輸、來源與查證、規則與語意）→切分（以下機制）→測試（回歸與模擬 transport）→比較（既有基線與修正結果）→驗收（VALIDATION_v1）。

## AI 本輪作的工程決定

1. **舊記憶生命週期**：C.1 寫命中自動 active，§8.1.5 寫由使用者裁定。採正文 §8.1.5，因其明確指定人的決策權；舊 API `mark_hit` 的預設保留相容，生產 caller 顯式傳 `reactivate_pending=False`。使用者可透過完整端點 ID 確認／停用整筆事件。
2. **top-30 與近因保底**：保留近因優先，將最後送模型的選取限制在 30 筆及字元預算內；完整本機記憶保留。
3. **來源證據**：年份／未具名章節不是來源；有可定位引用也僅代表格式可追溯，不宣稱外部內容已查。
4. **向後相容**：維持原始 Claude 預設 model；環境範本明示選擇白皮書的 Haiku 模型。未把過去成本估算當成所有模型的保證。
5. **交付邊界**：不修改白皮書、不合併 main、不部署既有線上服務；以 PR 保留可審閱變更。原始碼遵循既有 Apache 2.0，白皮書文件授權仍獨立；README 原先誤寫兩者皆 Apache，依本輪提供的白皮書更正。

## 待 MOMO 裁決的規格

- **情緒三軸的正式定義**：採 Arousal / Valence / Control、保留七情 / 偏好 / 心情，或兩套並存且各自命名？若新增前者，需要範圍、信心、觸發與退出冷卻條件；不能將既有七情分數假裝換算成心理量尺。
- **完整語意治理**：CIP-X 的語意距離如何量測？危險方向與「連續不滿但 AI 推進」如何結構化？元動機受益者方向遇到多人混合時如何定主導？六步／八階每步驗收輸出需補正式規格。
- **外部驗證來源**：要使用哪些來源工具／資料集、可用權限與成本？目前沒有搜尋後端，不可把 `/check` 改名為「已外部查證」。

## 尚未驗證

歷史 244 筆、500 題、19 題模型比較與商業／臨床效益，均未在本輪重跑。白皮書內部「第一輪有一家辨識 Haiku」與「累計無人辨識」等統計口徑不一致，亦未靜默修正文稿。待原始 log 與外部獨立評估，不以本輪 AI 分析背書。
